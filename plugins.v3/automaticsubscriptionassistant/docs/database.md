# 数据库生命周期与维护

本文描述 v3 当前源码。只维护 v3；v2 不采用此数据库布局。

## 管理边界与目录

| 目录 | 职责 |
| --- | --- |
| `db/models/` | 独立的 SQLAlchemy Base 和表模型，向宿主声明模型清单 |
| `db/oper/` | 使用调用方 Session 的 SQL 操作；不建表、不提交、不关闭连接 |
| `database/lifecycle.py` | 版本兼容检查、Alembic 升级、结构检查、Session 提交/回滚/关闭 |
| `database/migrations/` | 标准 Alembic `env.py` 与只追加的 `versions/`；不放在 HTTP `api/` 中 |
| `database/legacy.py`、`database/blacklist.py` | 旧 KV 数据归档、校验、导入、检查点与失败重试 |
| `database/backup.py` | 插件实例快照、升级前备份、停机维护恢复 |
| `schemas/` | 媒体身份、候选、历史、结果及忽略规则的数据契约；不包含 ORM 表 |
| `services/` | 历史事务、竞争重试及黑名单校验与匹配 |
| `api/` | 按配置、来源、历史、订阅、概览、黑名单拆分 HTTP 端点及路由声明 |
| `__init__.py` | 宿主生命周期、依赖装配、任务与入口注册 |

数据访问直接使用新的服务层和模型目录，不提供旧模块转导、旧 KV CRUD 或执行器回退。执行器必须显式注入当前实例的 SQL 黑名单服务。已发布数据的升级由初始化迁移处理，日常读写不再访问旧存储。

宿主通过公开 SDK `get_database()` 提供实例隔离的句柄：SQLite 使用实例专属 `plugin.db`，PostgreSQL 使用实例专属 schema。插件不自行选用宿主主库，不删除库文件，不释放宿主共享引擎。停用仅停止任务，正常卸载的句柄释放由宿主负责；只有宿主明确执行删除插件数据时才销毁数据目录或 schema。

## 数据表与清理语义

| 表 | 内容 | 清理行为 |
| --- | --- | --- |
| `subscribe_history` | 展示历史、来源候选快照、媒体身份、目标季与剧集组 | 可按保留条数修剪，或由用户显式删除 |
| `subscribe_handled` | 成功事实、精确候选别名、首次榜单归属 | 不随展示修剪删除；显式删除/清空相应历史会解除对应事实 |
| `subscription_blacklist` | 忽略规则 ID、去重指纹与完整别名 | 仅由用户移除规则，不随历史清理或取消订阅删除 |
| `database_state` | 旧 KV 黑名单接管检查点 | 不随历史清理删除，防止收尾重试复活用户已删除的规则 |
| `alembic_version` | 数据库迁移版本 | 由 Alembic 管理，不手工 stamp 或清空 |

provider 的可重建缓存和插件配置仍使用宿主 KV，宿主真实订阅仍由主程序管理。本库不保存第二份宿主订阅表。

## 初始化、升级与失败恢复

1. 停止旧任务，设置旧一轮的退出信号。抓取不必等待；最终订阅提交与停止信号使用同一把锁。
2. 检查已有 revision。库中出现当前包不认识的版本时拒绝启动，不自动降级。
3. 已有 SQL 库需要升级时，先在实例数据目录的 `database-backups/` 保存一致逻辑快照。SQLite 另外使用 `sqlite3.backup` 保存包含 WAL 已提交内容的完整 `.sqlite` 文件，并执行完整性检查。备份失败阻止升级。
4. 执行 Alembic 到 head。`asa_0001_history` 接管未版本化的旧表并补列、回填通用来源身份和整数年份、建立独立成功账本及索引；`asa_0002_blacklist` 添加忽略规则与状态表；`asa_0003_music` 保存音乐实体类型、艺术家与专辑。迁移脚本固定声明当时的结构，不导入可变的当前 ORM 模型。新增结构变更追加 revision，可在插件目录执行 `alembic -c database/alembic.ini revision -m "说明"` 创建模板，不改写已发布 revision。运行时连接由宿主注入，INI 不保存连接 URL。
5. 检查表、字段、主键及关键唯一约束。版本表还在而数据表丢失时拒绝继续，不把损坏库悄悄补成空库。
6. 归档并导入旧 KV 历史及黑名单。全部必要步骤完成后才标记数据库就绪，随后处理清空历史和立即运行开关、允许注册 cron。

宿主在 `init_plugin()` 之后才确保插件数据库，因此插件初始化主动调用同一迁移树，避免先读库后建表。宿主后续再次执行升级是幂等操作。迁移入口复用 `config.attributes['connection']`；PostgreSQL 禁止自行创建未限定 schema 的连接。SQLite 显式开启迁移事务，DDL 中断后可回滚并重试。不支持生成离线迁移 SQL。

移除进程永久的“engine 已建表”缓存；每次新服务首次访问会核对结构，每个事务都会核对版本。数据库在运行期间被换成其它版本时停止该操作，要求重新加载插件。

失败时 `get_state()` 返回假，`get_service()` 不再提供任务，手动运行与历史重新识别/补充订阅也返回未就绪；一次性开关保留，修复原因并重新加载后可以重试。`GET /status` 的 `database.ready/error` 给出就绪状态与初始化原因；此时历史统计为 `null`，不冒充空历史。

## 旧 KV 接管

历史源为 `history`，归档为 `history_migrated_backup`，完成标记为 `history_migration`。归档必须写入并回读一致后才能导入。逐条失败保留待重试源；已有数据库记录不被旧 KV 覆盖。完全无法解析时保留原源并停止自动任务；混合批次中无法解析的记录留在归档供排查。

黑名单源为 `subscription_blacklist`，归档为 `subscription_blacklist_migrated_backup`。保留旧规则 ID、别名、范围与时间；整批规则与接管指纹在同一个 SQL 事务内提交，损坏规则使整批回滚。删除旧 KV 失败时，下次按 SQL 检查点继续收尾，不重新导入已被用户删除的规则。

宿主 KV 与插件 SQL 是两个存储，不能宣称跨库 ACID。实现通过归档回读、迁移前后源值比较、SQL 检查点和幂等重试保障可恢复；接管期间不要再让旧版本进程修改同一实例的 KV。检测到源变化会保留数据并停止任务。

## 日常事务与并发

服务层负责短事务，正常提交，异常回滚，所有路径关闭 Session。历史行和成功别名在同一事务写入；已有成功状态与首次榜单归属不被过滤或异常覆盖。唯一键竞争时，历史写入在新的事务内重试一次。黑名单使用按行插入/删除，不用整表快照覆盖 SQL。

进程内共享锁串行化 Alembic 上下文和数据库事务，兼容内存 SQLite 的单连接测试；黑名单锁同时覆盖最终检查与订阅提交。停止信号到达后不再提交新的订阅，旧任务也不再按旧保留设置修剪新一轮历史。跨进程只由数据库约束保护存储；本插件不提供跨进程自动订阅任务的分布式锁。

## 备份与停机维护恢复

`DatabaseBackup(handle.engine, handle.plugin_id, plugin.get_data_path() / 'database-backups')` 提供：

- `export()`：返回包含实例、格式、revision、四张业务表和 SHA-256 校验的 JSON 对象。
- `create()`：生成新的人工逻辑快照文件。
- `before_upgrade()`：只在已有 SQL 库需要升级时生成升级前快照；相同 revision 的正常重载不重复生成。
- `restore(snapshot, stopped=True, mode='merge')`：校验实例、版本、表结构和忽略规则后，在一个事务中合并；保留已有成功事实与来源。
- `restore(snapshot, stopped=True, mode='replace')`：显式替换四张业务表；恢复前同样备份当前数据，失败则整体回滚。历史自增 ID 重新分配，避免 PostgreSQL 序列冲突，业务身份键不变。

快照文件采用受管文件名、0600 权限、临时文件写入、fsync 和回读校验后发布；不覆盖旧文件。备份按需创建，暂不自动轮转删除，管理员可在验证长期归档后清理旧文件。

恢复属于停机维护接口，没有在线恢复 HTTP 路由。调用前须停止并等待全部在途任务结束，也停止其它访问该实例的进程；`stop_service()` 本身不会等待网络抓取退出，不能仅调用它后立即宣称已静止。`stopped=True` 是维护调用方的显式承诺，不是服务内部自动判断。

逻辑恢复只接受当前 head 的同一实例完整快照，拒绝其它实例、未知表、损坏校验或旧结构直接覆盖。升级前 SQLite 完整备份可由管理员在所有实例进程退出后通过 SQLite 备份协议恢复，随后使用匹配的插件包；PostgreSQL 的旧结构回退使用宿主完整数据库备份或管理员迁移，插件不自动执行 downgrade。配置、旧 KV 归档和 provider 缓存不在当前 SQL 逻辑快照中，需要保留宿主备份。

## 验证

后端测试覆盖空库、未版本化旧库、升级幂等、未知版本、缺表/缺约束、DDL 失败回滚、Session 提交失败、并发首次访问、KV 归档校验/收尾重试、成功账本保留、停用中断和快照恢复回滚。SQLite WAL 完整备份单独验证。

`test_database_postgresql.py` 仅在显式设置 `ASA_TEST_POSTGRES_URL` 时连接测试库，在随机 schema 内验证真实 PostgreSQL 迁移、旧身份回填、恢复后继续写入、宿主连接保持开放及同名表隔离。本轮使用独立 PostgreSQL 16 测试容器验证，不访问用户数据库。

## 订阅配置升级

从 3.4.1 起，启动时自动将旧榜单选项与筛选条件迁移为独立规则。保留来源调度、启停、通知和代理等共享设置；禁用的组合转为禁用规则，空选择仍为空。迁移前将完整原配置备份至插件数据目录的 `config-backups/before-rules-<SHA256>.json`，写入并回读校验成功后才启动任务。无法等价迁移、备份或写入失败时保留原配置并停止任务，配置页显示错误并阻止覆盖保存。已有新规则（包括显式空规则）不重新迁移。首次未配置的来源仍提供预设卡片。

配置备份独立于 SQL 快照，只写入当前插件实例数据目录，权限为 0600，不通过 API 返回文件内容。相同配置重复升级复用同一备份；备份损坏时拒绝覆盖。需要恢复时应先停用插件并备份当前宿主配置，再由管理员将原始 JSON 恢复到该实例的宿主插件配置中，重载后重新迁移。

若已在 3.4.0 中保存空规则并覆盖旧设置，插件无法凭空恢复已丢失的条件；应从升级前的宿主备份恢复，或手动重新配置。已有空规则不自动恢复，避免重新启用用户主动删除的规则。
