# 动画与音乐榜单

v3.4.0 新增 AniList、Spotify、苹果音乐榜单、网易云音乐和腾讯音乐，共十个来源。各来源默认停用，独立配置启用、定时、代理和运行通知；通知默认关闭，位于「来源与调度」。

## 独立规则卡片

十个来源统一使用「榜单规则 → 配置规则」弹窗，主页面只显示规则数量与启用数量。在管理弹窗内添加、编辑或移除卡片，点击「应用」写回来源草稿，再保存插件配置；取消管理弹窗会丢弃本次改动。每张卡片可命名、启停、编辑与移除；停用保留条件。网易云/腾讯的榜单选择支持搜索与分组，腾讯采用官方巅峰榜、地区榜、特色榜和全球榜分组。

每张规则保存到 `options.rules` 列表，含 `id/name/on` 和该来源支持的条件。空列表停止监听，不自动补回默认规则。通知仍按来源统一设置。非法条件、重复规则和越界数量会被拒绝；每个来源最多 100 张卡片。本轮使用新的规则配置，不读取旧的平铺选项来拼装规则，已有自定义来源设置应在保存前重新检查卡片条件。

同一作品命中多张卡片时合并命中轨迹，只执行一次识别/订阅；仍按媒体身份和季号区分续季。历史卡片显示全部命中规则。每条规则须分别通过自身的全部筛选条件；满足任意一条完整规则即可，不能把两条规则各自通过的一半条件拼接。单条规则抓取失败后继续处理其它规则，来源最终报告部分失败。停止期间收集到的候选不进入订阅。

## 分享与导入

每个来源的规则管理弹窗左下角，从左到右为「导入、分享、清空」图标按钮，与主程序规则组使用相同的导入/分享图标。分享当前弹窗中的全部规则草稿，可复制 JSON 或下载；不包含来源开关、通知、代理、定时及用户归属。清空只修改本次管理草稿，取消弹窗可放弃。

分享格式 `moviepilot.automatic-subscription-assistant.rules` 的 `formatVersion` 当前为 `1`，同时保存 `pluginId`、生成时 `pluginVersion`、`provider.id/name`、`createdAt`、字段语义快照 `schema` 和 `rules`。插件版本从 Python 入口读取后嵌入构建，不手写前端版本；规则导入时重建本地 ID。

导入支持粘贴或选择 JSON 文件（最多 1 MiB、100 条规则）。来源 ID 必须与当前来源一致，异源、缺少版本、无效格式或未来分享格式会拒绝。预览显示生成版本、当前版本、规则明细和重复统计。默认追加并跳过相同条件；也可选择替换，仍只写入弹窗草稿，之后须「应用」及保存插件配置。

同源旧插件版本在当前字段检查通过后可复用，并提示版本差异。字段快照用于校对：新增可选字段会补当前默认值并逐项提示；缺少必填项、不支持的旧字段/值、类型或默认语义变化会拒绝静默转换，保留原 JSON 供人工校对。后续分享格式变化需增加明确的格式升级处理，不按插件版本号猜测配置映射。

## AniList

使用 [AniList GraphQL 参考](https://docs.anilist.co/reference/) 的 `Page.media(type: ANIME)`，按趋势、人气、评分、收藏数排序，分别组合不限时间、本季、下季或指定年份/季度（含全年），并独立选择动画形式、条数。高级筛选支持播出状态、题材、标签原名、出品国家和评分，均在官方查询端生效；题材和标签多选按 AniList 的 `genre_in/tag_in` 语义匹配。默认提供正在流行、本季新番两张卡片和年度动画电影预设。每榜 1–500 条，最多每页 50 条；按 `pageInfo.hasNextPage` 继续获取。下季新番会正确跨年。

候选保留 `media_source=anilist` 和作品 ID，电影单独标为电影，其余标为剧集；不强行补第一季。明确季号继续由原有识别管线解析，未确定目标季时保留为未识别。GraphQL `errors`、限流及错误结构均视为失败，不冒充空榜单成功。

## Spotify

使用公开接口 `https://charts-spotify-com-service.spotify.com/public/v0/charts` 返回的全球周榜，分别读取 `trackMetadata` 和 `albumMetadata`。每张规则最多 50 条，同一轮多张规则复用一次公开接口响应，保存艺术家、封面与平台对象 ID。艺术家榜不是可直接订阅的单曲或专辑，不提供为订阅选项。当前不承诺该公开端点未提供的国家榜或历史期数。

## 苹果音乐榜单

在统一的「榜单规则 → 配置规则」中，每张规则单独选择一个地区、一个榜单及条数。例如美国 iTunes 专辑 15 条、日本 Apple Music 热播歌曲 30 条，只请求明确设置的两条规则。默认提供美国热播歌曲规则。

配置保存为 `options.rules = [{id, name, on, country, chart, limit}, ...]`。不再提供地区矩阵或多元组装，停用规则会保留条件，清空规则停止监听。非法地区、榜单及重复规则在网络请求前拒绝。

- v2 热播歌曲：`https://rss.applemarketingtools.com/api/v2/{country}/music/most-played/{size}/songs.json`，读取 `feed.results`。
- iTunes：`https://itunes.apple.com/{country}/rss/topsongs/limit={limit}/json` 或 `topalbums`，读取 `feed.entry`，解析艺术家、所属专辑、发行日期及封面。

v2 是定长 Feed，按 10/25/50/100 档抓取足量后截取所需条数，**没有添加不存在的 `page`/`offset` 参数**。插件列表的分页或滚动展示独立于上游 Feed。不同地区、榜单中相同平台对象按音乐实体类型去重。

## 网易云音乐

目录采集接口：`GET https://music.163.com/api/toplist`。歌曲读取接口：`GET https://music.163.com/api/playlist/detail?id={id}`。从 `result.tracks` 读取歌曲、结构化艺术家、专辑、封面与发行年。只获取元数据，不调用播放、音频下载或会员接口。

## 腾讯音乐

请求 `https://u.y.qq.com/cgi-bin/musicu.fcg`，始终显式携带 `Referer: https://y.qq.com/`。目录通过 `musicToplist.ToplistInfoServer.GetAll` 采集；抓取使用 `GetDetail`，传入固定 `topId`、`offset=0`、有界 `num` 和空 `period`（最新一期）。

榜单选择沿用官方固定 topId；地区、曲风等已经包含在各个固定榜单中，不另行组合不存在的榜单。自动监听最新一期，不提供任意日期推测历史期数。

榜单排序来自 `req_1.data.data.song`，艺术家与专辑元数据通过 `songInfoList` 按歌曲 ID 关联，保留多艺术家署名。接口外层和 `req_1` 层错误码都检查。

## Mikan、热门媒体、豆瓣与奈飞

- Mikan：每张卡片独立选择本季、上季、下季或指定年份/季度，自动季度按 UTC 计算并正确跨年。详情补全与代理仍由来源统一设置。
- 热门媒体：每张卡片独立设置电影/剧集、风格、总获取条数（1–500）、评分及订阅人次。风格选项随电影/剧集切换，多选按任一风格匹配；后两种阈值在统计结果中筛选，不冒充服务端未知能力。仍需开启宿主订阅数据共享。
- 豆瓣：每张卡片选择一个内置榜单或一个完整自定义 RSS 地址，分别设置评分、年份、媒体类型。内置源依赖 RSSHub，不属于豆瓣公开官方 API；RSSHub 基址和代理由来源统一设置。
- 奈飞：全球规则分别选择最新周榜/史上最热、四种全球类型及每榜数量，可同时监听两种数据集。地区周榜也在同一规则弹窗内选择一个国家及电影/剧集类型，不套用全球英语/非英语分类。缓存按实际请求组合区分，命中缓存时也按当前规则名重新记录轨迹。
- 猫眼：在规则弹窗中选择电影票房榜，或选择网播热度榜并指定单个平台、网播类型及条数。每条规则独立设置年份/类型筛选；不提供平台矩阵。跨平台命中同一候选会保留各规则名称。

## 音乐识别与持久化

榜单平台 ID 仅表示原始候选，不伪装成 MusicBrainz 或其它宿主音乐来源的 ID。先构造宿主 SDK 的 `MetaMusic`，携带艺术家、单曲/专辑类型、专辑、年份和可用 ISRC，交给宿主音乐识别。显式填写宿主音乐来源 ID 时按该规范身份识别。

识别结果必须仍为音乐且实体类型一致，并且艺术家/别名存在匹配或 ISRC 一致。无法确认的条目保留为未识别，不按同名单曲或其它歌手的翻唱直接订阅。最终通过宿主原生订阅链提交规范来源、ID 和 `music_type`，不会强加影视季号。

音乐身份键包含单曲/专辑类型；无 ID 的展示身份还包含艺术家，避免同名作品相互覆盖。历史、成功账本和活动订阅索引使用一致的音乐身份。电影和剧集既有候选键不因增加音乐字段而改变。

历史支持音乐类型筛选、展示艺术家、补充编辑与黑名单；音乐名称规则需填写艺术家，已知 ID 的规则按类型和 ID 匹配。取消订阅并忽略沿用先保存规则再取消的顺序。源记录、实体类型、艺术家及专辑由插件数据库与快照一并保存，迁移版本为 `asa_0003_music`。

宿主须提供官方 `MetaMusic`、`MusicInfo` 与原生音乐识别/订阅能力。本轮核对官方 3.0.3 已导出使用的音乐 SDK 符号，完整业务验证使用当前本地开发宿主。真实榜单抓取只验证元数据，不创建用户订阅；音乐落地通过隔离测试验证。

检测到旧平铺榜单/筛选配置且尚未保存新规则时，停止自动监听并要求重新设置；配置页显示空规则，防止把旧条件静默替换为默认规则。首次未配置的来源仍提供预设卡片。

规则 ID 生成不依赖仅在安全上下文提供的 `crypto.randomUUID`：普通 HTTP 局域网访问也能添加和编辑规则。规则 ID 仅用于本地配置标识，不承担身份认证。
