# 自动订阅助手审查修复记录

对应 2026-10-23 的 18 项审查问题。共有问题同时修复 v2 和 v3，SQL 数据库与 KV 迁移问题仅涉及 v3，旧快照覆盖问题仅涉及 v2。

## 修复清单

| 编号 | 处理结果 | 主要实现 |
| --- | --- | --- |
| 01 | 明确的目标季贯穿查重、媒体库检查、订阅与历史；特别篇 0 保留 | `core/executor.py` 在快速路径前解析标题，复制宿主媒体对象后补入目标季；多季且目标不明时记为未识别 |

| 03 | 第一季不能通过任意季键拦截第二季 | `core/dedup.py` 仅在剧集目标季明确时走快速查重 |

| 07 | 成功状态不被过滤/错误降级 | 独立成功账本与首次成功记录保护；展示历史修剪不删除成功事实 |

| 10 | 英语史上最热不再误抓普通周榜 | 无对应富页时回退所选数据集 TSV，国家富页仍可独立抓取 |

| 12 | 自定义保存 API 校验写入结果并刷新任务 | 持久化明确失败时不初始化；成功后刷新宿主注册的定时任务 |

| 14 | 未识别记录可从菜单重新识别 | 历史页对 `error/unrecognized` 均提供入口 |
| 15 | 卡片明确显示目标季和剧集组 | 历史与管理卡片标题显示 S00/S01/S02，存在剧集组时显示其标识 |
| 16 | 猫眼日期正确区分过去和未来 | 验证绝对日期，按明确文案解析相对天数，未知格式不拼接数字猜年份 |
| 17 | 过期全选请求正常结束加载 | v3 独立全选请求序号；过滤、后续请求或退出多选后不采纳旧响应 |
| 18 | 短路历史记录也保留识别出的季 | 过滤、媒体库已存在、订阅已存在分支传递统一目标季；历史保存原始候选供重试 |

## 数据与兼容行为

v3 在原历史表补充候选键、原始候选 JSON，并新增 `subscribe_handled` 存储规范身份和精确候选别名；均在插件自有库中幂等建表/补列。v2 保留原历史 KV 格式，成功事实与别名单独保存在 `history_handled`。

已存在的成功历史继续作为查重依据。修剪 v3 展示历史不会解除处理状态；显式删除对应历史或清空全部历史才解除对应成功事实和别名。按来源清空时，也解除其他来源指向该成功身份的别名。

原始候选快照用于重新识别，保留来源身份、原始标题、季和过滤元数据。旧版没有快照的历史继续使用原字段还原。重试不再先删除原记录，只有新结果实际保存后才移除旧身份键。

多季但没有可靠目标季的候选会保留为未识别，需要确认来源标题或在宿主中手动订阅目标季。这是防止误订第一季的明确行为。历史记录不自动批量纠正或删除，现有订阅和生产数据也未被脚本改动。

v2 的订阅 Oper 导入兼容已迁移目录的宿主，并保留旧目录回退。为验证 v2，额外测试依赖只安装到 `/tmp/asa-v2-test-deps`，未修改宿主虚拟环境。
