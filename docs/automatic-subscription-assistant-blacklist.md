# 自动订阅助手：黑名单

本文说明 `plugins.v3/automaticsubscriptionassistant` 3.2.0 中的黑名单功能。后续仅维护、测试和发布 v3；v2 保留历史版本，不再同步更新。主使用文档见[自动订阅助手 v3](../plugins.v3/automaticsubscriptionassistant/README.md)。

## 使用入口

- 插件详情和配置页顶部的独立「黑名单」标签：按名称、发行年份范围和类型筛选、分页查看、手动添加、移除规则。
- 支持插件侧栏的宿主：「订阅」分组下的「自动订阅助手」，使用 `mdi-rss` 订阅图标，默认进入黑名单。专用联邦入口 `AppPageBlacklist` 透传到 `AppPage`，复用插件数据页；侧栏需插件总开关及至少一个有效来源启用，且用户具备订阅权限。
- 订阅历史卡片的「更多 → 加入黑名单」：保留现有订阅，仅阻止以后自动添加。
- 订阅管理卡片或多选操作的「退订并加入黑名单」：先保存规则，再取消订阅。

普通「退订」继续保留原来的语义。希望长期忽略某部影视时，请使用「退订并加入黑名单」。在宿主其他页面已经退订的影视，也可从插件历史添加，或手动填写黑名单。

列表和添加弹窗复用订阅历史、筛选与搜索的布局与样式：统一上置字段标签、紧凑控件、卡片网格、空状态、加载骨架及桌面/移动端分页。侧栏入口也复用插件数据页，保持相同的页头和标签导航。

## 匹配范围

电影按媒体身份忽略；剧集可忽略全部季或指定季，季号 `0` 表示特别篇。批量退订并忽略默认覆盖选中影视的全部季。

从历史添加时保留原始来源身份和识别后的身份，识别前后都会检查。整剧 TMDB ID 的匹配会覆盖各季不同的豆瓣 subject ID，同时区分电影与电视剧的 ID 空间。相同名称但不同 ID 的媒体不会因为名称相同而被 ID 规则拦截。

手动添加时可选择 TMDB、豆瓣或 Bangumi 并填写 ID。豆瓣/Bangumi 的剧集往往每季使用不同 ID，因此「全部季」规则会先识别并补充整剧 TMDB 身份；识别失败会提示改用 TMDB ID、名称规则或指定季，不会宣称已成功忽略整剧。

不填 ID 时，按完整名称和类型匹配，可用发行年份进一步限定。名称比较忽略大小写、首尾空白及连续空白，不做关键词包含匹配。名称存在别名时建议使用 ID。

## 持久化与失败处理

黑名单使用独立插件 KV 键 `subscription_blacklist`，不随历史清理、保留条数修剪、订阅删除或插件重启而删除。忽略结果使用 `blacklisted` 状态，不写入成功去重标记。已有成功历史保留其成功事实。

移除黑名单只移除忽略规则，下次运行重新按原有过滤和去重规则评估，不会立即创建订阅；已有成功历史仍参与去重。

KV 写入失败时不退订；退订失败时保留已保存的忽略规则，并将失败项返回前端重试。规则更新与最终「复查规则 + 创建订阅」共用进程内锁，防止同一宿主进程中运行中的候选绕过新规则。

## 验证

v3 后端回归覆盖黑名单存储、季号/特别篇、电影与剧集 ID 隔离、来源别名、整剧识别、名称规则、移除后重新评估、运行中添加规则、持久化/退订失败、API 鉴权及侧栏声明。前端行为测试覆盖提交、失败反馈、部分失败重试、列表响应顺序、筛选草稿、共享分页与标签导航；构建包含侧栏的通用和专用入口。

浏览器验证分为开发壳内存 API 预览和独立 MoviePilot v3 测试实例。预览验证过历史添加指定季、退订并加入黑名单和移除规则；真实测试实例验证过侧栏加载、手动添加、刷新后持久化、筛选及移除。添加弹窗与历史筛选弹窗的宽度、字号、控件高度和间距已对比，390px 窄屏无横向溢出。上述验证不代表生产环境的实际下载或跨来源在线识别均已验证。
